# BUSINESS.md

completeness_level: complete

## Problem
AI growth experimentation platform for measuring paid-acquisition experiments with human approval and governance. addresses an explicit operational need inside the Alfares ecosystem and keeps the project intent documented and reviewable. The repo is owned by the project team and is not treated as a generic placeholder.

## Target users and stakeholders
- Product owner and operational team for growth
- Alfares platform operators responsible for deploy and validation governance
- downstream service consumers and ecosystem partners that depend on the repository output

## Value proposition
The repository reduces ambiguity by pairing project intent, operational constraints, and implementation evidence in one place. It allows the project to be governed without copying the shared IPS framework into a live runtime system.

## Goals
- keep the project purpose and scope explicit
- preserve traceability from goals to execution plans to validation evidence
- maintain a truthful onboarding profile that matches the repository reality
- align with the wider Alfares ecosystem standards without inventing runtime behaviour

## Non-goals
- creating a synthetic runtime for a repo that does not own one
- encoding unverified business claims or user counts
- replacing the shared IPS standard with a local fork

## Success metrics
- all required IPS onboarding artifacts exist and are valid
- validator passes without placeholder or invented contract signals
- project state and validation debt remain honest and reviewable
- repository intent remains traceable to the underlying real service or hub purpose

## Business constraints
- Production changes must remain aligned with the actual service or hub owner responsibilities.
- Documentation must not fabricate runtime dependencies, users, or workflows.
- The repo must remain truthful about low-priority, documentation-led, or hub-only status.
