# Vision

completeness_level: complete

## One-sentence vision
AI growth experimentation platform for measuring paid-acquisition experiments with human approval and governance.

## Problem statement
The repository must preserve the real project boundary with truthful documentation so the ecosystem can understand what it owns and what it intentionally does not own.

## Target users
- project owner and operational staff
- internal platform operators
- users and downstream systems that depend on the repository boundary

## Core user need
A clear, reviewable adoption profile that reflects the actual service purpose without introducing false runtime assumptions.

## Key outcomes
- clear repository scope
- valid trustable onboarding profile
- honest integration review and project traceability

## Non-goals
- inventing service capabilities that do not exist
- copying the IPS framework into this repo as a detached, drifting local standard

## Success criteria
- IPS validator passes for the planning phase
- capability review decisions are concrete and truthful
- docs remain aligned to the project owner and ecosystem expectations
